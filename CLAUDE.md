# geo-alert — инструкция для агента

## ВАЖНО: при старте каждой сессии

1. Прочитай `tasks/BOARD.json`
2. Определи какие задачи доступны (status=`todo`, все depends_on в `merged`) и какие роли свободны
3. **Сразу предложи пользователю варианты** — в каком агенте работать и какую задачу взять, используй AskUserQuestion

## Что это за проект

Веб-приложение: пользователи создают карты и оставляют на них гео-метки. При приближении к метке — уведомление. Стек: Go + Gin + PostgreSQL/PostGIS (backend), React + TypeScript + Leaflet (frontend).

Полный дизайн и corner cases: `PLAN.md`

## UI: дизайн-система

**Перед написанием любого frontend-кода** — прочитай `DESIGN.md`. Там: цвета, шрифты, тени, радиусы, список компонентов и их пропсы, z-index архитектура.

## Как начать работу

### 1. Прочитай текущее состояние задач

```
tasks/BOARD.json   — все задачи, статусы, зависимости
tasks/AGENTS.md    — протоколы: старт, взятие задачи, heartbeat, восстановление после сбоев
```

### 2. Следуй протоколу старта агента (tasks/AGENTS.md)

```
1. Захватить tasks/BOARD.lock
2. Проверить active_agents — найти свободную роль (backend → frontend → ops)
3. Если все роли заняты — сообщить и остановиться
4. Записать себя в active_agents с last_heartbeat_at
5. Освободить lock
6. Взять первую доступную задачу своей роли
```

### 3. Задача доступна если

- `agent` = моя роль
- `status` = `"todo"`
- все `depends_on` имеют `status` = `"merged"`

### 4. Лимит параллельных задач

Не более **3** задач одновременно (`config.max_parallel_tasks`).

## Протокол завершения задачи (обязательно)

После выполнения каждой задачи, **перед тем как брать следующую**:

```
1. git merge feature/TASK-X.X → main
2. Захватить BOARD.lock → status: "merged", merged_at: now() → освободить lock
3. Обновить CHANGELOG.md:
   - Добавить раздел ### [TASK-X.X] Название
   - Перечислить выполненные микрозадачи (чекбоксы)
   - Указать созданные/изменённые файлы
   - Указать ветку
4. git commit CHANGELOG.md
5. git push origin main
```

`CHANGELOG.md` находится в корне репозитория. Ведётся в хронологическом порядке — новые записи добавляются в конец текущей сессии.
