## Условные обозначения

- `→ сервер` — данные, отправляемые на сервер
- `← сервер` — данные, получаемые от сервера
- `✓` — успешный кейс
- `✗` — неуспешный кейс
- `[auth]` — требует JWT токен в заголовке `Authorization: Bearer <token>`
- `[optional auth]` — токен необязателен, но меняет ответ при наличии

## 1. Аутентификация

### 1.1 Первый вход / регистрация через Google

**Предусловие:** пользователь не авторизован, открыл приложение.

**Шаг 1 — Пользователь нажимает «Войти через Google»**

Система открывает Google OAuth диалог.  
→ (frontend) формирует URL: `https://accounts.google.com/o/oauth2/v2/auth?client_id=...&redirect_uri=...&scope=openid email profile&response_type=code`

**Шаг 2 — Пользователь выбирает аккаунт Google и даёт разрешение**

Google редиректит на `VITE_GOOGLE_REDIRECT_URI?code=<authorization_code>`.

**Шаг 3 — Обмен кода на токены**

```
POST /auth/google
→ { "code": "<authorization_code>", "redirect_uri": "<VITE_GOOGLE_REDIRECT_URI>" }
```

| Кейс | Условие | ← Ответ сервера |
|------|---------|-----------------|
| ✓ Новый пользователь | code валиден, email не существует | `201` `{ "access_token", "refresh_token", "user": { id, email, display_name, avatar_url, ... } }` — создаётся аккаунт |
| ✓ Существующий пользователь | code валиден, email уже в БД | `200` `{ "access_token", "refresh_token", "user": {...} }` |
| ✗ code истёк | Google вернул ошибку | `400` `{ "error": "invalid_grant" }` |
| ✗ redirect_uri не совпадает | несоответствие с зарегистрированным в Google | `400` `{ "error": "redirect_uri_mismatch" }` |
| ✗ code отсутствует | пустое поле | `400` `{ "error": "code required" }` |
| ✗ Аккаунт удалён (soft delete) | `deleted_at IS NOT NULL` | `403` `{ "error": "account deleted" }` |

**Шаг 4 — Сохранение токенов**

Frontend сохраняет `access_token` (15 мин) и `refresh_token` (30 дней) в localStorage / Zustand store.

---

### 1.2 Обновление токена

**Предусловие:** `access_token` истёк, `refresh_token` ещё действителен.  
Происходит автоматически через axios-интерцептор при получении `401`.

```
POST /auth/refresh
→ { "refresh_token": "<token>" }
```

| Кейс | Условие | ← Ответ |
|------|---------|---------|
| ✓ | refresh_token валиден и не истёк | `200` `{ "access_token", "refresh_token" }` — старый refresh_token инвалидируется |
| ✗ Истёкший | refresh_token старше 30 дней | `401` `{ "error": "token expired" }` → редирект на `/login` |
| ✗ Невалидный | подделан или не найден в БД | `401` `{ "error": "invalid token" }` → редирект на `/login` |
| ✗ Пользователь удалён | аккаунт soft-deleted после выдачи токена | `403` `{ "error": "account deleted" }` |

---

### 1.3 Получение данных текущего пользователя

**Предусловие:** пользователь авторизован. Вызывается при загрузке приложения.

```
GET /auth/me  [auth]
→ (нет тела)
```

| Кейс | ← Ответ |
|------|---------|
| ✓ | `200` `{ id, email, display_name, avatar_url, bio, is_private, created_at }` |
| ✗ Нет токена | `401` `{ "error": "unauthorized" }` |
| ✗ Токен истёк | `401` → интерцептор пробует refresh |

---

### 1.4 Выход

**Предусловие:** пользователь нажал «Выйти».

```
POST /auth/logout  [auth]
→ { "refresh_token": "<token>" }
```

| Кейс | ← Ответ | Поведение системы |
|------|---------|-------------------|
| ✓ | `200` `{}` | refresh_token удаляется из БД; FCM token очищается; frontend удаляет токены из storage, редирект на `/login` |
| ✗ Невалидный refresh_token | `400` | frontend всё равно очищает локальное состояние |

## 2. Профиль пользователя

### 2.1 Просмотр своего профиля

Данные берутся из `GET /auth/me` или Zustand store. Отдельного endpoint нет.

**Отображается:** display_name, avatar_url, bio, is_private, дата регистрации, количество публичных карт.

---

### 2.2 Просмотр чужого профиля

```
GET /users/:id  [optional auth]
→ (нет тела)
```

| Кейс | Условие | ← Ответ |
|------|---------|---------|
| ✓ Активный пользователь | пользователь существует и не удалён | `200` `{ id, display_name, avatar_url, bio, is_private, card_count, created_at }` |
| ✓ Удалённый пользователь | `deleted_at IS NOT NULL` | `200` `{ id, display_name: "Удалённый пользователь", avatar_url: null, ... }` — профиль-заглушка |
| ✗ Не найден | UUID не существует | `404` `{ "error": "user not found" }` |
| ✗ Заблокирован | смотрящий заблокирован владельцем профиля | `403` `{ "error": "forbidden" }` |

**Карты пользователя:**

```
GET /users/:id/cards  [optional auth]
→ ?limit=20&offset=0
```

| Кейс | ← Ответ |
|------|---------|
| ✓ | `200` `{ "cards": [...], "total": N }` — только публичные карты, если смотрит не владелец |
| ✓ Владелец смотрит | возвращаются все карты включая приватные |
| ✓ Пустой список | `200` `{ "cards": [], "total": 0 }` |
| ✗ Пользователь удалён | `404` |

---

### 2.3 Редактирование профиля

**Предусловие:** пользователь авторизован, находится в настройках профиля.

```
PUT /users/me  [auth]
→ { "display_name": "...", "bio": "...", "avatar_url": "..." }
   (все поля опциональны, но хотя бы одно должно присутствовать)
```

| Кейс | Условие | ← Ответ |
|------|---------|---------|
| ✓ | данные валидны | `200` `{ user: { ... обновлённые данные ... } }` |
| ✗ Все поля пустые | запрос без изменений | `400` `{ "error": "no fields to update" }` |
| ✗ display_name > 100 символов | | `400` `{ "error": "display_name too long" }` |
| ✗ bio > 150 символов | | `400` `{ "error": "bio too long" }` |
| ✗ Не авторизован | | `401` |

**Эффект:** display_name и avatar_url обновляются везде — в комментариях, метках, истории. Исторические записи сохраняют новое имя (нет снапшотов).

---

### 2.4 Удаление аккаунта

**Предусловие:** пользователь нажал «Удалить аккаунт» и подтвердил.

```
DELETE /users/me  [auth]
→ (нет тела)
```

| Кейс | ← Ответ | Поведение системы |
|------|---------|-------------------|
| ✓ | `200` `{}` | soft delete пользователя; cascade soft delete всех его карт и меток; инвалидация всех сессий (refresh_tokens); очистка FCM token; редирект на `/login` |
| ✗ Не авторизован | `401` | |

**Corner cases:**
- Метки удалённого пользователя на чужих картах → остаются (orphan, `created_by` остаётся но пользователь удалён)
- Профиль отображается как «Удалённый пользователь» везде
- Аватар → стандартная иконка «удалён»

## 3. Карты

### 3.1 Создание карты

**Предусловие:** пользователь авторизован, нажал FAB на главном экране.

**Шаг 1 — Открывается CreateCardModal**

Поля: `title` (обязательное), `description`, `is_public` (toggle, default: true).

**Шаг 2 — Пользователь заполняет форму и отправляет**

```
POST /cards  [auth]
→ { "title": "Моя карта", "description": "...", "is_public": true, "ttl_hours": 0 }
```

| Кейс | Условие | ← Ответ |
|------|---------|---------|
| ✓ | данные валидны | `201` `{ "card": { id, owner_id, title, description, is_public, radius: 200, ttl_hours: 0, marker_count: 0, subscriber_count: 0, view_count: 0, created_at } }` → редирект на `/cards/:id` |
| ✗ title пустой | | `400` `{ "error": "title required" }` |
| ✗ title > 200 символов | | `400` `{ "error": "title must not exceed 200 characters" }` |
| ✗ Не авторизован | | `401` |

---

### 3.2 Просмотр карты

```
GET /cards/:id  [optional auth]
→ (нет тела)
```

| Кейс | Условие | ← Ответ |
|------|---------|---------|
| ✓ Публичная карта | `is_public = true` | `200` `{ card: { ...поля... }, markers: [...] }` |
| ✓ Владелец просматривает приватную | авторизован как owner | `200` — полный доступ |
| ✗ Приватная карта | чужой пользователь | `403` `{ "error": "forbidden" }` |
| ✗ Карта не найдена | UUID не существует или soft-deleted | `404` `{ "error": "card not found" }` |
| ✗ Заблокирован | owner заблокировал смотрящего | `403` |

**Счётчик просмотров:** `view_count` карты инкрементируется при каждом GET (только сервер, без отдельного запроса).

---

### 3.3 Список меток карты

```
GET /cards/:id/markers  [optional auth]
→ ?limit=50&cursor=<created_at>&sort=recent|popular&include_drafts=false&include_expired=false
```

| Кейс | ← Ответ |
|------|---------|
| ✓ | `200` `{ "markers": [...], "next_cursor": "..." \| null }` |
| ✓ Владелец | видит черновики (`is_draft=true`) при `include_drafts=true` |
| ✓ Владелец | видит `view_count` каждой метки |
| ✗ Чужой пользователь | `include_drafts` игнорируется, черновики не возвращаются |
| ✓ Пустая карта | `{ "markers": [], "next_cursor": null }` |

---

### 3.4 Редактирование карты

**Предусловие:** пользователь — владелец карты.

```
PUT /cards/:id  [auth]
→ { "title": "Новое название", "description": "...", "is_public": false, "ttl_hours": 0 }
```

| Кейс | Условие | ← Ответ | Поведение |
|------|---------|---------|-----------|
| ✓ | владелец, данные валидны | `200` `{ "card": { ...обновлённые данные... } }` | |
| ✓ Карта стала приватной | `is_public: false` | `200` | Все подписчики получают in-app уведомление `CARD_PRIVATE` и теряют доступ мгновенно |
| ✓ Карта стала публичной | `is_public: true` | `200` | Подписчики, ранее потерявшие доступ, не восстанавливаются автоматически |
| ✗ Не владелец | другой авторизованный пользователь | `403` |
| ✗ title > 200 символов | | `400` |
| ✗ Не авторизован | | `401` |

---

### 3.5 Удаление карты

**Предусловие:** пользователь — владелец карты, подтвердил удаление.

```
DELETE /cards/:id  [auth]
→ (нет тела)
```

| Кейс | ← Ответ | Поведение |
|------|---------|-----------|
| ✓ | `200` `{}` | soft delete карты; cascade soft delete всех меток; фото меток асинхронно удаляются из Firebase Storage; все подписки на карту удаляются |
| ✗ Не владелец | `403` |
| ✗ Карта не найдена | `404` |

## 4. Метки

### 4.1 Создание метки

**Предусловие:** пользователь авторизован, находится на карте, нажал на карту (только владелец карты).

**Шаг 1 — Клик по карте**

Frontend перехватывает `MapClickHandler` → открывает `CreateMarkerModal` с предзаполненными `latitude`, `longitude`.

**Шаг 2 — Заполнение формы**

Поля: `title`*, `description`, `images[]`, `tags[]`, `allow_comments`, `allow_likes`, `is_draft`, `notifications_enabled`, `notification_type`, `expiration_type`, `expires_at`.

**Шаг 3 — Отправка**

```
POST /cards/:id/markers  [auth]
→ {
    "title": "Кофейня",
    "description": "Отличный эспрессо",
    "latitude": 50.4501,
    "longitude": 30.5234,
    "images": ["https://storage.googleapis.com/..."],
    "tags": ["кофе", "еда"],
    "allow_comments": true,
    "allow_likes": true,
    "is_draft": false,
    "notifications_enabled": true,
    "notification_type": "ON_ENTER",
    "expiration_type": "ETERNAL",
    "expires_at": null
  }
```

| Кейс | Условие | ← Ответ |
|------|---------|---------|
| ✓ | все обязательные поля, карта существует, пользователь — owner | `201` `{ "marker": { id, card_id, created_by, title, ..., like_weight: 0, comment_count: 0 } }` |
| ✓ Пользователь уже в радиусе метки | сервер проверяет `notification_cooldowns` | push / WS уведомление отправляется сразу |
| ✗ title пустой | | `400` `{ "error": "title required" }` |
| ✗ title > 200 символов | | `400` `{ "error": "title must not exceed 200 characters" }` |
| ✗ images > 5 | | `400` `{ "error": "max 5 images allowed" }` |
| ✗ tags > 5 | | `400` `{ "error": "max 5 tags allowed" }` |
| ✗ latitude / longitude отсутствует | | `400` `{ "error": "latitude required" }` |
| ✗ Не владелец карты | другой авторизованный | `403` |
| ✗ Карта не найдена / удалена | | `404` |
| ✗ Rate limit | > 20 меток / час | `429` `{ "error": "rate limit exceeded", "retry_after": N }` |
| ✗ Не авторизован | | `401` |

**Диалог «метка в радиусе другой»:** если новая метка попадает в радиус существующей — система предупреждает, но не блокирует.

---

### 4.2 Просмотр метки

Пользователь кликает по маркеру на карте → открывается `MarkerDetailDrawer`.

```
GET /markers/:id  [optional auth]
→ (нет тела)
```

| Кейс | Условие | ← Ответ |
|------|---------|---------|
| ✓ | метка активна | `200` `{ marker: { id, title, description, latitude, longitude, images, tags, like_weight, comment_count, allow_comments, allow_likes, is_draft, notification_type, expiration_type, expires_at, created_at } }` |
| ✓ Владелец метки | `created_by == current_user_id` | + `view_count` в ответе |
| ✓ Истёкшая метка | `expires_at < now` и ещё не удалена TTL-воркером | `200` с пометкой, кнопки редактирования недоступны |
| ✗ Метка удалена (soft) | | `404` `{ "error": "marker not found" }` |
| ✗ Метка — черновик | `is_draft=true`, смотрит не owner | `403` |

**После открытия — запись просмотра:**

```
POST /markers/:id/views  [auth]  (или session-based для анонимов)
→ { } + Header: X-Session-ID: <uuid>
← 204 (no content)
```

`view_count` инкрементируется только для уникальных сессий. Виден только владельцу.

---

### 4.3 Редактирование метки

**Предусловие:** пользователь — автор метки (`created_by == user_id`). Владелец карты чужую метку не редактирует.

```
PUT /markers/:id  [auth]
→ { "title": "...", "description": "...", "images": [...], "tags": [...], "allow_comments": true, "is_draft": false, "notification_type": "BOTH", "expiration_type": "UNTIL_TIME", "expires_at": "2026-12-31T23:59:59Z" }
```

| Кейс | Условие | ← Ответ |
|------|---------|---------|
| ✓ | автор, метка активна, данные валидны | `200` `{ "marker": { ...обновлённые данные... } }` |
| ✓ Продление TTL | `expires_at` устанавливается дальше в будущее | `200` — обратный отсчёт обновляется в UI |
| ✗ Редактирование истёкшей метки | `expires_at < now` | `409` `{ "error": "cannot update expired marker" }` |
| ✗ Не автор метки | другой пользователь | `403` |
| ✗ title > 200 символов | | `400` |
| ✗ images > 5 | | `400` |

---

### 4.4 Удаление метки

**Предусловие:** автор метки ИЛИ владелец карты (только удаление, не редактирование).

```
DELETE /markers/:id  [auth]
→ (нет тела)
```

| Кейс | ← Ответ | Поведение |
|------|---------|-----------|
| ✓ Автор удаляет | `200` `{}` | soft delete метки; фото асинхронно удаляются из Firebase Storage; `marker_count` карты декрементируется; всем пользователям в радиусе метки отправляется уведомление `MARKER_DELETED_IN_RADIUS` |
| ✓ Владелец карты удаляет чужую метку | тот же результат | + уведомление автору метки |
| ✗ Ни автор, ни владелец карты | `403` |
| ✗ Метка уже удалена | `404` |

---

### 4.5 Список меток поблизости

```
GET /feed/nearby  [optional auth]
→ ?lat=50.4501&lon=30.5234&radius=500&limit=20&cursor=<cursor>
```

| Кейс | ← Ответ |
|------|---------|
| ✓ | `200` `{ "markers": [...], "next_cursor": "..." \| null }` — метки в радиусе, не удалённые, не истёкшие |
| ✓ Авторизован | из ответа исключаются метки заблокированных пользователей |
| ✓ Пусто | `200` `{ "markers": [], "next_cursor": null }` |
| ✗ lat / lon отсутствует | `400` `{ "error": "lat and lon are required" }` |

## 5. Фотографии

### 5.1 Загрузка фото

**Предусловие:** пользователь добавляет фото при создании или редактировании метки.

```
POST /upload/photo  [auth]
→ multipart/form-data: field "photo" = <binary>
```

| Кейс | Условие | ← Ответ |
|------|---------|---------|
| ✓ | JPEG / PNG / WEBP, ≤ 10MB | `200` `{ "url": "https://storage.googleapis.com/geo-alert/photos/..." }` — URL сохраняется в `marker.images[]` |
| ✗ Поле photo отсутствует | | `400` `{ "error": "field 'photo' is required" }` |
| ✗ Файл > 10MB | | `413` `{ "error": "file too large" }` |
| ✗ Неверный формат | magic bytes не совпадают (не JPEG/PNG/WEBP) | `400` `{ "error": "unsupported file type" }` |
| ✗ Файл слишком мал | < 4 байт | `400` |

**Порядок:** сначала загружается фото → получается URL → URL включается в тело запроса `POST /cards/:id/markers` или `PUT /markers/:id`.

**При удалении метки / карты:** все URL из `marker.images[]` удаляются из Firebase Storage асинхронно.

---

### 5.2 Просмотр галереи фото в метке

Отображается в `MarkerDetailDrawer`. Предыдущее / следующее фото управляются в UI. Запросов к серверу нет — URL уже в данных метки.

## 6. Лайки и дизлайки

### 6.1 Постановка / снятие лайка / дизлайка

**Предусловие:** пользователь авторизован, `allow_likes = true` у метки.

```
POST /markers/:id/likes  [auth]
→ { "type": "LIKE" }   // или "DISLIKE"
```

**Toggle-логика:**

| Текущее состояние | Действие | Результат | Δ like_weight |
|-------------------|----------|-----------|---------------|
| Нет голоса | LIKE | +лайк | +1 |
| Нет голоса | DISLIKE | +дизлайк | -1 |
| LIKE | LIKE | удалить лайк | -1 |
| DISLIKE | DISLIKE | удалить дизлайк | +1 |
| LIKE | DISLIKE | переключить | -2 |
| DISLIKE | LIKE | переключить | +2 |

| Кейс | Условие | ← Ответ |
|------|---------|---------|
| ✓ | авторизован, `allow_likes=true` | `200` `{ "like_weight": N, "user_vote": "LIKE" \| "DISLIKE" \| null }` |
| ✗ `allow_likes = false` | владелец отключил лайки | `403` `{ "error": "likes disabled for this marker" }` |
| ✗ Rate limit | > 100 лайков / час | `429` |
| ✗ Метка не найдена / удалена | | `404` |
| ✗ Не авторизован | | `401` |

**Real-time обновление:** после успешного ответа сервер через WS рассылает `{ type: "like_update", marker_id, like_weight }` всем подключённым пользователям.

**Optimistic update:** UI меняет счётчик мгновенно, откатывает при ошибке ответа.

**Цвет маркера:** `like_weight` → цвет пина автоматически пересчитывается в UI:
- `< 0` → серый `#9CA3AF`
- `0–2` → тёмно-серый `#6B7280`
- `3–5` → жёлтый `#FBBF24`
- `6–10` → оранжевый `#F97316`
- `> 10` → красный `#EF4444`

## 11. Геолокация и уведомления

### 11.1 Запрос разрешения геолокации

**Шаг 1 — При первом открытии приложения**

Браузер запрашивает `navigator.geolocation.watchPosition`.

| Кейс | Поведение системы |
|------|-------------------|
| ✓ Разрешено | GPS слежение активно, позиция пользователя отображается красным кружком на карте |
| ✗ Отклонено | кружок не отображается; кнопка «Моя позиция» в UI недоступна или показывает объяснение |
| ✗ Недоступно (HTTP, не HTTPS) | геолокация не работает в браузере |

---

### 11.2 Обновление геолокации на сервере

**Происходит при каждом значимом перемещении пользователя.** Frontend отправляет координаты.

```
POST /users/me/location  [auth]
→ { "lat": 50.4501, "lon": 30.5234, "accuracy": 15.5 }
```

| Кейс | Условие | ← Ответ | Поведение |
|------|---------|---------|-----------|
| ✓ | координаты валидны, `accuracy < 100м` | `200` `{ "nearby_markers": [...] }` — метки в радиусе | сервер проверяет все метки в радиусе; если cooldown не активен → push + WS уведомление |
| ✓ Несколько меток в радиусе | | один push: «Вы рядом с X, Y, Z» |
| ✓ `accuracy > 100м` | GPS слабый | `200` + предупреждение в UI «Низкая точность GPS» |
| ✓ Cooldown активен | пользователь уже получал уведомление об этой метке и не выходил | пропустить уведомление |
| ✓ Пользователь вышел из радиуса | `last_left_at` обновляется | cooldown сбрасывается, следующий вход → новое уведомление |
| ✗ lat / lon отсутствует | | `400` `{ "error": "lat and lon required" }` |
| ✗ Не авторизован | | `401` |

**Cooldown:** повторное уведомление о той же метке не ранее чем после выхода из радиуса и повторного входа (хранится в `notification_cooldowns`).

---

### 11.3 Push-уведомления (FCM)

**Шаг 1 — Запрос разрешения**

```
// frontend
Notification.requestPermission()
```

| Кейс | Поведение |
|------|-----------|
| ✓ Разрешено | Service Worker регистрируется; FCM token получается |
| ✗ Отклонено | push не работает; используется только in-app Toast при триггере WS |

**Шаг 2 — Сохранение FCM token**

```
POST /users/me/fcm-token  [auth]
→ { "token": "<FCM_registration_token>" }
← 200 {}
```

**Шаг 3 — Получение push**

Сервер через FCM отправляет push при входе пользователя в радиус метки. Service Worker (sw.js) перехватывает событие `push` и показывает системное уведомление.

| Кейс | Поведение |
|------|-----------|
| ✓ Приложение в фоне / закрыто | системное push-уведомление ОС |
| ✓ Приложение открыто | WS-сообщение → Toast в UI (без дублирования push) |
| ✗ FCM token устарел | сервер очищает токен, последующий FCM cleanup worker убирает невалидные |
| ✗ Нет интернета | push не доставляется; повторной попытки нет |

**Клик по push:**

Service Worker обрабатывает `notificationclick` → открывает приложение на странице связанной метки (`data.url`).

## 15. WebSocket: real-time события

### 15.1 Подключение

```
WS /ws  [auth]  (JWT в query: ?token=<access_token>)
```

| Кейс | Поведение |
|------|-----------|
| ✓ | соединение установлено; сервер хранит `client` в менеджере |
| ✗ Невалидный токен | WS закрывается с кодом `4001` |
| Reconnect | exponential backoff (1s → 2s → 4s → … → max 30s) |
| Несколько вкладок | каждая вкладка — отдельное соединение; уведомление получают все, но toast показывается в активной |

---

### 15.2 Ping-Pong (keepalive)

Сервер отправляет ping каждые 45 сек. Клиент отвечает pong. Если pong не получен за 60 сек — соединение закрывается, клиент переподключается.

---

### 15.3 Входящие сообщения (клиент ← сервер)

| Тип сообщения | Payload | Действие на клиенте |
|---------------|---------|---------------------|
| `like_update` | `{ marker_id, like_weight }` | обновить счётчик и цвет маркера в UI без перезагрузки |
| `new_comment` | `{ marker_id, comment: { id, user, text, created_at } }` | prepend комментария в открытом drawer |
| `new_notification` | `{ notification: { id, type, message, ... } }` | prepend в панели уведомлений + инкремент badge + Toast |

## 17. Rate Limiting

Применяется ко всем endpoint'ам. При превышении:

```
← 429 Too Many Requests
   { "error": "rate limit exceeded", "retry_after": <seconds> }
   Header: Retry-After: <seconds>
```

| Действие | Лимит |
|----------|-------|
| `POST /cards/:id/markers` | 20 меток / час / пользователь |
| `POST /markers/:id/likes` | 100 лайков / час / пользователь |
| `POST /markers/:id/comments` | 50 комментариев / час / пользователь |
| `POST /subscriptions` | 200 подписок / день / пользователь |
| Любой endpoint | 1000 запросов / час / IP |

**Поведение UI:** при `429` показывается Toast с сообщением «Слишком много запросов. Попробуйте через N секунд».

## Сводная таблица HTTP-кодов

| Код | Смысл | Типичная причина |
|-----|-------|-----------------|
| `200` | OK | успешный GET / PUT |
| `201` | Created | успешный POST |
| `204` | No Content | успешный DELETE / запись просмотра |
| `400` | Bad Request | невалидные данные, отсутствующие поля |
| `401` | Unauthorized | нет / истёкший / невалидный токен |
| `403` | Forbidden | нет прав (не owner, заблокирован, приватная карта) |
| `404` | Not Found | сущность не найдена или soft-deleted |
| `409` | Conflict | дубликат (лайк, подписка, жалоба), конфликт состояния (expired marker) |
| `413` | Payload Too Large | файл > 10MB |
| `429` | Too Many Requests | rate limit |
| `500` | Internal Server Error | непредвиденная ошибка сервера → Toast «Произошла ошибка, попробуйте позже» |
